# 可复制 Prompt 的组装模式

这些不是强制模板；按任务实际复杂度有选择地填入。**首要任务是让另一个 AI 知道该做什么、用什么、怎么检验、如何交付。**

## A. 标准：研究与复杂决策

```text
我的真实目标是：[要促成的决策/变化]。
当前要交付：[用户明确要求的成果]。
已知背景与不可改变的约束：[人、市场、时限、成本、格式、权限、禁忌]。

不要只做表面总结。先从[指定的一手资料、原始日志、源文件、权威数据]核实关键事实，标注来源和日期；资源不可访问时如实说明，并采用可用的替代证据，不要编造。

按以下路径工作：
1. 定义成功指标，并找出最可能影响结果的关键变量。
2. 用[领域内具体方法/分析工具]还原事实、比较可选方案，并列出证据链。
3. 主动挑战我的重要假设[具体假设]：寻找反例、替代解释、相反数据，不要预先接受我的结论。
4. 借助[确有增量价值的其他领域的具体工作方法]补全盲点；明确不适用之处。
5. 区分已证实、合理推断与待验证的发现；给出按优先级排序的行动、取舍和风险。
6. 使用[第三方数据/样本外/测试/真实客户反馈/可核验验收]独立验证，无法验证时报告限制和补证步骤。

最终以[用户期望的输出格式]呈现，先给结论及下一步。避免套话、假装有权限、模型自评当证据。
```

## B. 工程：从修单点问题升级为可持续结果

```text
目的：[保持长期结果，如可靠性/质量/可维护性]；当前具体交付仍包括：[明确的待修复缺陷]。
环境与权限：[代码仓库/版本/设备/日志/是否可运行测试]。
先基于原始[错误日志/复现步骤/代码]诊断根因，而不是仅修改表面报错；可访问环境时实际复现，建立失败测试。

实施最小可靠修复；执行[编译、单测、集成/回归测试、设备复现]并报告可验证结果。
检查该问题是否来自跨版本、状态同步或流程中的系统性原因；仅在可行时提出[监控、日志映射、警戒值、自动化回归]，使同类问题更早暴露。

交付：[明确修改点/文件、测试输出、未解决风险和下一步]。不声称执行未运行的测试；未经授权不部署或改写其他系统。
```

## C. 创意：尊重作品本身，不强行升维

```text
完成[用户明确要的创作成果]，目标观众和使用场景是[... ]。
作品要让观众[理解/感知/行动]，同时保留[审美、调性、媒介、品牌、篇幅等硬约束]。
借鉴[相关专业：视觉叙事/摄影/信息设计/材料工程等]的具体方法： [构图、光线、质感、信息层次或其他适用方法]。
提出[有意义的选项/决策标准]并依[真实观看或用户反馈方式]核对效果；不要把品牌口号、夸张话术代替实际作品。
输出[可直接使用的稿/图像生成提示词/分镜等]。
```

## D. 递进野心：保真 → 任务优化 → 机制改造

保真版：把原任务的对象、动作、条件、格式写明确，必要时加入可检查的质量标准；不改题。

增强版：保留交付物，把它同**真正的决策结果**连接，增加**原始资料、专业方法与外部检验**。

God 版：在增强版之上，识别是否值得将**反复人工驱动的步骤设计为具备数据入口、反馈、验证和回退的系统**，同时加入有界的高目标与跨学科方法；**不擅自激活自动化或扩大权限**。

## E. 依赖信息不全时的句式

- `[缺失的关键信息，例如市场/平台/截止日期]`；优先用已给背景推断，若不可靠则保留占位。
- “若能访问[数据库/浏览器/代码执行/官方文件]，使用它；否则说明数据边界，给出下一步获取最小证据的方案。”
- “把[挑战性指标]作为优先冲刺目标；如受硬件、物理或成本限制，先测当前基线，展示约束和最优可达结果。”
- “以[外部指标]验收；不要只给模型对自己结果的评分。”
- “不要以‘缺少上下文’直接终止；列明影响最大的缺口，在不影响可靠性的范围内继续完成可证实部分。”

## F. 默认回答排版

```markdown
**优化后 Prompt**

[一份可独立运行的完整提示词；通常直接使用清楚的小标题分段]

**核心升级**
- [一句目标层升级]
- [一句方法或原始数据升级]
- [一句验证/跨域的真实增益]
```

用户要“只给 Prompt”时：只有完整提示词，不要“核心升级”。用户要多版时：首推最优版，并给最有信息量的差别；不要生成 5 份近似版本。
