# Prompt God · 实战输入 / 输出样例

这些例子用来校准**重写结果的质量与粒度**，不是在 Skill 激活时自动执行。要根据用户原任务保留约束、素材、时效和目标模型。例子里的数值与产品是假设性或用户示例，**不得当作已核实数据**。

## 1. 文章原例：QBR，表格→决策→机制

**原始 Prompt**
> 这些是这个季度的数据，用公司模版做一份 QBR PPT。

**增强后的 Prompt（保留 PPT）**

> 基于所给季度经营数据，制作一份管理层能够直接用于决策的 QBR PPT，沿用给定公司模板，不能只替换旧数据。
>
> 先核对指标定义、数据粒度与时间范围；在可访问底层数据时分析用户、收入、留存、成本的变化及可能驱动因素，明确相关和因果证据的边界。
>
> 让管理层在 30 分钟内看清：本季度**发生了什么、为什么、下一步该做什么**。找出最迫切的三个资源或战略决策，为每个决策提供支持证据、反对证据、替代路径、主要风险与负责人建议。
>
> 对关键假设进行对抗性检验；重要指标要有可回溯数据源。最终交付 PPT 和一页决策备忘单，并注明哪些结论尚缺独立验证。

**当用户明确授权机制创新时，才再升维**：

> 不止改进 PPT。判断季度评审是否满足“尽早发现经营问题、把人和钱放在正确位置”的真实目的；设计一个能比季度报告更早识别异常的机制，用历史数据回测提前量和误报率，再提出与现行 QBR 并行运行一个季度的评估计划。仍交付本季度 PPT，另附机制设计和运行条件，不擅自上线。

**迁移点**：交付物不变 → 决策提升 → 在明确授权下设计持续机制。完整对应文章 Altitude 四级演进。

## 2. 文章原例：改 bug → 保持产品稳定

**原始 Prompt**
> 帮我修复应用崩溃。

**优化后的 Prompt**

> 目标不只是让眼前报错消失，而是减少这一类崩溃再次发生；**当前首要交付仍是这次崩溃的可验证修复**。
>
> 如有权限，先读取原始 crash report、堆栈、复现路径、用户设备与应用版本，并映射到确切的 git commit。区分单例错误与系统性问题，寻找最小可复现案例及根因。不要猜测源码或谎称已复现。
>
> 对相关 Windows/macOS/Linux 环境，**仅在真实可用且与产品相关时**完成编译、复现、回归；添加失败可复现的测试、实施最小修复、再次运行测试，并保存测试结果与影响范围。
>
> 另外评估是否需要将 crash 报告入口、版本映射、回归测试和告警做成常态闭环；说明所缺的权限和工具，不擅自部署。
>
> 输出：根因证据、修复文件与代码说明、实际运行过的测试及结果、剩余风险、预防复发的最小工作流。

**迁移点**：需要底层日志 + 版本映射 + 真实运行环境，才能让“持续无崩溃”有意义。

## 3. 出海创业研究：从产品清单到机会证伪机制

**原始 Prompt**
> 帮我找几个适合中国供应链、在美国卖得好的产品，我想创业。

**优化后的 Prompt**

> 目标不是生成热门品类清单，而是找到**中国小团队在美国市场能以可控成本验证、存在真实未满足需求、具备合理单位经济性的细分机会**。
>
> 已知边界：[团队规模]；[可投入资金]；[主要渠道如 Amazon]；[可接受的法规/供应链限制]；[验证周期]。如有缺失，保留占位并在不影响研究的前提下继续。
>
> 请从独立的一手证据入手：真实购买/差评与退货原因、用户任务场景、竞品真实功能及价格、渠道规则、需求季节性、供应链工艺和 BOM。不要只引用选品榜、单一博主或未经核实的销量估算。
>
> 使用用户研究的 JTBD 方法把“买某类产品”改写成“完成某个生活/工作任务”；使用产品工程与供应链视角评估可复制差异化；使用财务/增长视角估算含物流与退货的单位经济性；使用对抗性竞争研究找出为什么现有卖家没解决问题。
>
> 必须主动证伪每个候选：是否仅为噪声差评？是否已有成熟替代？用户是否愿为改进付费？是否无法低成本制造或进入市场？以证据强弱和验证成本排序，允许全部 PASS。
>
> 只输出最值得验证的 1–3 个方向。每项包括证据链接与日期、反证、最小样机/MVP、30–90 天可执行实验、成功/失败门槛、预算假设。对拿不到一手证据的指标明确标注未知，不臆造成交数据。

**迁移点**：Altitude（从选品转为可重复证伪机会）× Depth（用户原始证据、BOM、单位经济）× Range（JTBD、产品、制造、竞争、财务）× 外部裁判（可执行实验）。

## 4. A 股研判：从“看图猜买卖”到证据驱动决策

**原始 Prompt**
> 这只股票今天阴包阳，要不要卖？

**优化后的 Prompt**

> 分析 [代码及名称] 在 [交易日期] 的 K 线是否构成严格意义上的阴包阳，并判断这一形态对**未来数日至一个月**风险收益的实际意义。目标是形成有条件的持仓应对方案，而不是根据单个形态武断下“卖出”结论。
>
> 先校验复权方式、开高低收、成交量/换手、所属行业与基准指数同期表现；结合近期趋势、关键价位、量价、情绪及公告时点。若当前行情和 Level-2 数据不可访问，必须说清时间边界，不可编造当日盘面。
>
> 以历史同类形态的**客观定义**说明其可能的样本偏差；不得把未经统计检验的口号说成概率。对立验证：哪些数据说明它是趋势转弱？哪些数据支持短期洗盘或假跌破？
>
> 输出：形态判定、支持/反对的证据、可能情景及触发条件、持有/减仓/退出的操作框架、止损和失效条件。无法获取成本、仓位和风险限额时，使用占位符，不自行假定。交易仍由我本人审批执行。

**迁移点**：不把“专家”当方法；用数据定义、对立证据、可观察风险触发代替绝对预测，并尊重权限。

## 5. 创意类：电商图片构图保留用户明确想要的“图片”

**原始 Prompt**
> 给特斯拉 Model 3 的 Alcantara 方向盘套做一张电商第一屏主图，看起来高级。

**优化后的 Prompt**

> 请生成**一张**适用于电商商品详情页第一屏的高质量商品主图，产品是 Model 3 专车适配的 Alcantara 材质方向盘套，重点传达“轮廓精准贴合、材质触感细腻、不显臃肿、装车后像原厂升级”。
>
> 采用豪华汽车产品摄影的真实材质、光线和结构语言；让方向盘成为清晰主角，展示关键轮廓与包覆边缘，避免把套子画成传统蓬松通用套。座舱背景克制，不干扰产品。画面构图应同时适应移动端第一屏的裁切与信息层级。
>
> 不擅自添加品牌授权徽标、凭空声称经过认证的性能或不存在的装车细节；若没有真实产品参考图，明确只能生成**概念性视觉方向**，不能宣称与实物完全一致。
>
> 输出要求：先给主视觉图；若无法直接生成，则给可交给图像模型的完整生成提示词。质量验收重点：小图缩略状态下主体识别清晰、轮廓真实、卖点可见；最终转化效果需要通过真实受众或 A/B 数据验证。

**迁移点**：创作任务以具体作品为核心，引用专业视觉方法；不要强制把它升维成运营系统。

## 6. 小任务：无需“God 模式”堆步骤

**原始 Prompt**
> 帮我把这句话改得礼貌一点，不要太长。

**优化后的 Prompt**

> 请把下面这句话改得更礼貌、自然、简洁。保持原意，不添加新承诺。只输出改写结果，不超过原文的 1.2 倍长度：
>
> [原句]

**迁移点**：高质量优化可以只有两句话。复杂工作流不适用于所有需求。

## 7. 错误模式对照

| 原始输入 | 不好的“优化” | 应该改成 |
|---|---|---|
| 做好 PPT | “你是世界顶级 PPT 大师，尽力做到最棒” | 明确该 PPT 要让谁理解什么、决定什么；补充数据和审查动作 |
| 用户流失是新手引导问题 | “深入分析并肯定这一结论” | 从原始日志复现或推翻此假设，找替代因素和可检验指标 |
| 找到客户提前流失信号 | “分析完自己给自己 100 分” | 样本外验证、误报率、提前量、稳定性，独立裁判 |
| 快速优化页面 | “必须 200 毫秒，不许说做不到” | 200 毫秒作为挑战目标，测基线、说明预算和硬约束、分阶段试验 |
| 要一张商品图 | “改写为市场战略与 CRM 自动化建设计划” | 优化构图、材料、真实呈现与目标受众感受，保留图片产物 |
| 组建专家团队 | “你是律师、空头、设计师、记者，请轮流演讲” | 分别进行证据核验、反例挖掘、视觉层级与法律边界审查 |
